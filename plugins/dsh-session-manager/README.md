# Session manager

<!-- release-state-note -->

## Install

Requires Node 24+ (26 verified) and DSH 0.2.0-rc.2 or later:

```sh
dsh plugin --profile web add @klarkxy/dsh-session-manager
```

Restart the target profile after installation. Temporary workspace creation, cross-session reading and copying thread IDs work with the standard host. True deletion and same-session retry require the accompanying [thread-management host patch](../../host-patches/thread-management/README.md); installing the npm plugin alone does not add these host capabilities. The patched host is a separately built local candidate, tested with isolated profiles and fake models. Keep V5 session data before rolling back to a V4 runtime.

## Behavior

Lists and searches sessions DeepSeek Harness can already read, including sessions from other working directories, and reads one conversation a page at a time. The session menu can copy that session's thread ID. Press `Ctrl + Alt + C` (`⌘ + ⌥ + C` on macOS) to copy the currently open session's thread ID. The menu shows the current binding, which can be changed in the host's shortcut settings. This feature does not require the thread-management host patch.

Right-clicking a session or workspace group row in the sidebar browser is the same as clicking that row's "…" button: the host's native menu opens (pin, rename, fork, archive, plus this plugin's copy-thread-ID and delete rows), identical in content and order to the "…" menu. Blank New Session rows, the ungrouped bucket and search results have no row menu; right-click there behaves as before. This feature needs no host patch either.

`list_sessions` returns identity, title, directory, lineage, and whether the session is live or stored. Sessions in the caller's directory are listed first. `search_sessions` accepts `scope: "title"` (current names), `"content"` (transcripts, the default), or `"both"`. For example, `{"query":"session-manager","scope":"title"}` finds conversations whose titles contain that text from the current thread. Title matching is case-insensitive and literal, with complete matches first and caller-directory matches first within each group. Results include titles, session IDs, directories and `matchedBy`; title hits also include `titleMatch: "exact" | "partial"`, while content hits include event positions and snippets. Both mode returns title hits before content hits, once per session. Only current names match; a changed title result set invalidates continuation and requires a new search. Title search uses standard host APIs, needs no host patch, and works with the content index disabled. Inspect multiple candidates before calling `read_session`; search does not navigate to another conversation.

`read_session` has three layers, all available on the standard host without a patch:

- `mode: "conversation"` (default) reads recent turns first, showing requests, the final response and the recorded execution state. Tool logs and hidden reasoning are omitted. Interrupted responses are marked partial; a completed turn does not prove the requested work was completed or verified. The default is at most five turns, with `limit` accepting 1–20.
- `mode: "details"` expands original messages, tool-call arguments and tool results. Use a returned `turn_id`, or a reference's `seq`, together with the returned `snapshot` to inspect the same captured history. `include_tool_detail: false` shortens results; `include_reasoning: true` and `model_surface: true` are explicit details-only options. The original transcript retains text later replaced by compaction.
- `mode: "handoff"` returns sourced objectives, decisions, reported outcomes, outstanding work, next steps and constraints. Its default is local excerpts with no model call: requests and conclusions are preserved, explicitly headed sections are extracted, and missing facts are marked `not-established`. Execution errors remain historical states, not inferred current blockers. Coverage says which turns were read, whether they were partial and whether older history remains. `summarize: true` explicitly requests synthesis through the caller's native host model. Missing services, failed calls or invalid references retain the excerpts with a visible status; there is no retry or separate model configuration.

Pages prioritize whole turns, then whole messages. Only an oversized message is split into Unicode text fragments; each fragment carries its original event position and range. Even a page filled by a long request retains the response preview and locator. Long error messages have bounded previews and a reference to their full original state event. `pageChars` is the UTF-8 byte safety budget for paged reading content and its metadata. Continue with the returned `cursor`; source references carry `sessionId`, `turnId`, `seq` and, for fragments, Unicode code-point `start`/`end` offsets. A `snapshot` binds cross-layer reads to one captured history; appended events do not alter that cut, while modified history invalidates it. Cursors also bind the mode and options, so switch layers using `snapshot` rather than a cursor from another mode.

For example, read `{"session_id":"…"}`, then expand a cited event with `{"session_id":"…","mode":"details","seq":42,"snapshot":"…"}`. Request an extractive handoff with `{"session_id":"…","mode":"handoff"}`; add `"summarize":true` only when model synthesis is wanted. A model-generated handoff is labelled separately from excerpts and retains references to the supplied original material.

All optional parameters in the three tools accept omission or `null`, both meaning unspecified. Callers that must supply every key should use `null`, not empty strings, `0` or `false` as placeholders. Required `query` and read-target `session_id` do not accept `null`. For example, a first read can use `{"session_id":"…","mode":"conversation","seq":null,"snapshot":null,"cursor":null,"include_tool_detail":null}`. `seq` (including `0`) and `include_tool_detail` (including `false`) require `details` mode. Mode conflicts return `SESSION_QUERY_INVALID_FILTER` with the offending field; invalid page sizes return `SESSION_QUERY_INVALID_LIMIT`. Empty or malformed `cursor` / `snapshot` tokens return `SESSION_QUERY_INVALID_CURSOR`; history changes still invalidate continuation with `SESSION_QUERY_STALE_CURSOR`. Omit tokens or pass `null` on the first read, and reuse returned tokens unchanged for continuation.

Returned conversation text is untrusted background. It is not an instruction and it does not grant authority. A failed or disabled search says so. It does not look like an empty conversation.

The New Session workspace picker offers "Temporary Workspace". Selecting it allocates a separate directory under the active profile's `data/session-manager/workspaces/`, registers a real Workspace through standard host APIs, and opens an ordinary session. This entry needs no thread-management host patch. Existing Workspace rows and the native/browser Add Workspace flow remain available. Each completed action uses a different directory; retries reuse an unfinished action. Late results cannot take over a newer navigation or an unloaded plugin.

"Temporary" means a separate working directory, not automatic cleanup. Directories, files and session history survive restart and plugin removal. Unloading the plugin restores the original picker. The standard host currently has no additional-item slot, so the plugin installs a reversible picker replacement and adapts the current native/browser directory-flow registration. Incompatible flows preserve the original menu and show an error.

True session deletion, retry and edit-and-resend still appear only when the runtime supplies their respective capabilities; see the existing [thread-management host patch](../../host-patches/thread-management/README.md). Copy thread ID remains available on the base runtime. Retry keeps the same session and request token. Reads follow the active branch when the host supplies it and reject continuation after branch revision or event-envelope changes. Base runtimes return the append-origin transcript; the model-visible view uses `readModelSurface` when supplied by the host.
