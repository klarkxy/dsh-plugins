# 安全自动（候选版）

自动审核原生沙箱提权请求。当真实的 `write`/`edit`/`bash`/`pwsh` 调用要求把沙箱放宽到 Workspace Write 之外时，由独立审核模型把关这一次调用——内置静态证明能判定为只读的 `bash` 命令除外，它们不调模型直接放行。通过就自动继续；其他审核结果会在当前会话显示完整操作，给你 60 秒选择“仅批准这一次”或拒绝。无人响应则到期拒绝。插件不会把整个会话切成 Full Access。

> **0.2.0 是破坏性简化。** 0.1.x 的精确规则预检、workspace/shell/escalation 候选名单、`shadow`/`smart`/`unattended` 模式、深度审核阶段和 HTTP 端点均已删除。见[从 0.1.x 迁移](#从-01x-迁移)。

## 安装与启用

```sh
dsh plugin --profile <profile> add @klarkxy/dsh-safe-auto
```

使用源码检出安装：

```sh
pnpm install --frozen-lockfile
pnpm --filter @klarkxy/dsh-safe-auto test
dsh plugin --profile <profile> add ./plugins/dsh-safe-auto
```

bundle 会插入 `dsh-safe-auto` 与 `dsh-safe-auto-ui` 两个 profile 条目。之后输入框的权限菜单里会在原生档位旁出现第四个选项——选择 **安全自动** 即为本会话启用，选回任意原生档位即停用。在此之前没有任何自动行为：会话不继承启用状态，重启、切换权限或卸载都会撤销它。插件页只保留审核配置、安全说明和只读的预算边界，按页签分区。

> 输入框的权限控件是替换型插槽：安装 Safe Auto 期间由插件自己渲染这个控件（包含原生档位），选项才能出现在菜单里。如果宿主以后重新设计这个控件，插件的副本在新版本跟进前可能落后。

## 工作原理

1. 原生工具调用请求 `sandbox_permissions` 提权（`workspace-write` 或 `danger-full-access`）。
2. 插件绑定当前活跃执行——agent、callId、signal、完整参数、cwd、沙箱策略，以及按时间排序的真人指令，包含后续限制和撤销。
3. 完全按字面解析的 `bash` 命令，只有每次调用都符合精确正向语法才会不收集证据、不调模型直接放行：区分大小写的 POSIX 程序名、支持的选项和值、只含输入的操作数数量、安全重定向和受限环境前缀。未知选项、缩写、未列出的短选项组合、输出文件操作数及仅赋值的语句继续审核。`ls -la`、`cat input | jq .name`、`grep -rn pattern src`、`find . -name "*.md"`、`ps aux` 等普通读取保留快速通道；`pwsh` 不走此通道。
4. 审核模型审查一次完整请求。Shell 调用会补充有界的工作区包配置和所引用本地脚本作为非可信证据；放行前重新核对路径与内容。
5. 审核通过返回 `allowed-once`。请求本身符合范围时，模型拒绝、不确定、故障或预算耗尽会进入限时人工确认。窗口显示完整操作、请求权限、审核意见和倒计时；明确批准后再次核对绑定及证据，只放行这一调用。拒绝、关闭窗口或超时返回 `rejected`，不交给下游审批器。

宿主禁止、结构性拒绝、证据变化、取消或请求失效不能被覆盖。人工确认需要 UI 条目和已认证的浏览器客户端；没有界面或把人工超时设为零时，保持原来的不放行处理。Headless 会话不会获得自动回退权限。

审核模型看到有界动作、按时间排序的真人指令和本地证据，不继承主代理提示词、隐藏推理或工具。授权按实际含义判断：完成开发任务所需的本地安装、构建和测试可以属于已授权工作，无须用户逐条点名命令。询问进度或说“继续”不会丢掉先前授权，后续限制仍然有效。只有低/中风险、至少中等授权且副作用有界才自动放行。

真人文本完整保留，合计最多 12 KiB。敏感文本、非文本约束或超限会阻止自动审查，不会静默丢掉限制；请求本身有效时，仍可在限时窗口中明确批准当前完整操作，不把这段历史发给模型。证据最多八个文件、每个 6 KiB、合计 12 KiB；受保护、越界、敏感或不可读内容会被标记并排除。证据并非完整安全证明：不会穷举依赖、导入代码或整个 workspace 的脚本，仍有实质不确定性时不得自动放行。

## 配置

全部可选；不配置时审核模型跟随当前对话。编辑 profile 条目的 `config` 并重载：

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `enabled` | `true` | 总开关。`false` 不挂载任何守卫。 |
| `provider` / `model` | *（跟随对话）* | 固定审核路由，用你的 DSH 模型 ID 成对配置。 |
| `reasoningEffort` | *（模型默认）* | 固定路由 advertised 的思考强度。 |
| `reviewerPrompt` | *（无）* | 额外审核约束（≤4096 字符）；只能收紧，不能放宽。 |
| `timeoutMs` | `30000` | 单次审查超时。 |
| `humanApprovalTimeoutMs` | `60000` | 独立于模型审查的人工确认窗口；`0` 关闭，最多 300000 ms，只在 profile 配置。 |
| `maxInputBytes` | `32768` | 提示词与输入合计的 UTF-8 字节上限；已有显式配置保持原值。 |
| `outputTokens` | `256` | 审核输出上限。思考模型可能需要更大。 |
| `maxReviewsPerTask` | `20` | 每个真人任务的审查次数上限。 |
| `consecutiveDenials` | `3` | 连续明确拒绝达到该值后熔断。不确定和故障重置拒绝计数，但仍消耗审查预算。 |
| `staticReadonly` | `true` | 可证明只读的 `bash` 提权不调模型直接放行；`false` 则一律送审核模型。 |

未知键会直接校验失败，而不是被忽略。审核模型、思考强度和提示词也可以在插件页配置；保存的值覆盖 profile 路由，但永远不覆盖预算。

## 审核模型

**默认：跟随对话。** `provider`/`model` 留空。每次审查从请求会话已接受的请求头解析 provider/model，复用 DSH 已配置的凭据——不需要额外 API key。继承的只有模型路由，不包括历史、提示词、工具或预算。

**固定模型。** 成对设置 `provider` 和 `model`，对话切换模型时审核路由保持不变。路由缺失或非法时直接拒绝，不做静默回退。

## 策略

| 请求 | 结果 |
| --- | --- |
| 绑定的 `write`/`edit`/`bash`/`pwsh` 单次提权，审查通过 | `allowed-once`，仅此一次 |
| 严格静态解析可证明只读的 `bash` 提权 | `allowed-once`，不调模型、不耗预算 |
| 受保护的凭据/安全文件、密钥、危险程序（完整解析的命令中任何位置） | 审查前硬拒绝 |
| 符合请求范围的模型拒绝（含风险意见）、不确定或审查故障 | 限时人工确认；未明确批准就不放行 |
| 未知工具、子代理、嵌套或未绑定请求 | 不自动放行 |
| 人工拒绝或确认超时 | 拒绝；再次执行须重新审查 |
| 证据变化、请求失效、审计故障或取消 | 不放行并给出终止原因 |

原生 `approval: never` 仍在任何应答者之前拒绝。不要与其他自动审批应答者叠加使用。

## 从 0.1.x 迁移

- profile 键 `mode`、`workspaceRoots`、`shellCandidates`、`escalationCandidates`、`endpoint`、`apiKeyEnv`、`tokenField`、`fast*`/`deep*` 以及熔断 `sessionBudgetUnits`/`totalDenials` 已删除；仍携带这些键的 profile 会校验失败。0.1.x 的 `approvalReview: true` 加插件页启用，现在就是唯一行为。
- `fastProvider`/`fastModel`/`fastReasoningEffort` 更名为 `provider`/`model`/`reasoningEffort`；`fastOutputTokens` 更名为 `outputTokens`；`fastCallsPerTask` 更名为 `maxReviewsPerTask`。
- 0.1.x 面板保存的设置仍可加载（废弃键会被剥离），但审核路由回退为跟随对话——如果你用过固定模型，请在插件页重新选择。

## 边界与限制

- **不是经过审计的安全边界。** 审核方是语言模型，可能出错，尤其在对抗性上下文中。保留你原本依赖的原生沙箱、隔离和备份。
- **静态证明以操作者信任 PATH 和运行时为前提。** 它检查原始命令文本，不核验已安装二进制、shell 函数或环境运行时的完整性。显式程序路径、`.exe`／`.cmd` 后缀、大小写变体、可执行 pager／配置环境前缀和会持久化的赋值都不符合条件。解析器或语法缺陷仍可能造成错误证明；这不是运行时认证，也不保证绝对安全。无法证明的命令回到审核／人工确认，不新增硬拒绝。
- **引号不能绕过硬拒绝。** 保护路径和秘密检查先读取解码后的字面参数、环境及重定向值，包括相邻引号片段拼接；退出静态通道时仍执行这些检查，模型或人工确认不能覆盖。引号旁的未引用通配符仍使静态证明失败。Bash 的 `/dev/tcp`、`/dev/udp` 文件重定向回到审核，包括引用过的路径及编号 fd 输入重定向；普通文件输入、fd 合并和 `/dev/null` 输出保留原有规则。
- **Git 的子命令名不能证明只读。** 裸 `git status`、工作区 diff、`git ls-files --modified` 及其他工作区内容检查继续审核，因为刷新和内容转换可能执行配置中的 clean/process filter。支持的对象／索引读取必须在原始参数中带 `--no-pager --no-optional-locks --no-lazy-fetch -c core.fsmonitor=false`；暂存区 diff 还需 `--no-ext-diff --no-textconv --ignore-submodules=all`。历史读取另需 `--no-show-signature` 和受支持的固定格式，例如 `--oneline`。插件不会补参数或重写命令。精确的 `git version`、`git --no-pager config --get user.name` 是独立的窄范围读取；传输 helper、编辑器、filter 和混合配置修改都不能走快速通道。普通 `sort` 可能写临时文件，因此只保留其检查模式。
- **独立确认通道。** 当前 DSH 0.2.0-rc.2 的审批和问答链允许自动应答器。人工确认改用插件已认证的浏览器 HTTP 入口和不可预测、单次使用的请求 ID。Fetch Metadata 与宿主的来源、认证检查用于防跨站请求，并不证明物理真人点击；已认证客户端、其传输层和同进程插件仍然可信。不向模型注册审批工具。
- **服务端掌握时限。** 请求发布后开始计时，用单调时钟判定到期，只接受第一个有效答案。重复、迟到和跨会话回答均失败。停用、修改设置、卸载或取消会使待审批失效；请求仅存内存，重启不会恢复。兼容直接浏览器请求与已认证的 DSH 桌面传输；不符合要求的请求类型仍会被拒绝。
- **其他插件的原生审批保持原生流程。** 没有 Safe Auto 自有执行上下文时，Blueprint 顺序审批、Classmates 模型审批会继续交给后续处理器。已有自有上下文中的不匹配、过期、已领取请求，以及无上下文却冒用 `bash`／`pwsh`／`write`／`edit` 的请求仍然关闭放行。
- **覆盖范围止于原生单次提权。** 只审核从 `workspace-write` 放宽的 `write`/`edit`/`bash`/`pwsh`。其他工具、MCP、远程执行、子代理调用和常驻权限变更都在自动范围之外。
- **证据会复核，执行并非原子操作。** 放行前复核证据路径、版本和 SHA-256 摘要，但审批与执行之间仍可能发生文件变化。同进程插件仍然可信，卸载会移除守卫；实际隔离仍依赖外部手段及受限的凭据与出站。
- **不作任何保证。** 没有 fail-open 选项，没有持久审计数据库，也不承诺绝对安全或节省比例。

## 验证

在本包运行 `npm test`、`npm run build` 和 `npm pack --dry-run`，以及仓库级 `pnpm check`。测试覆盖路由、并发会话、原生流、上限、过期决定、模型服务移除、执行绑定，以及真实 Cordis/ToolRuntime/ApprovalService/LlmRuntime 契约。CI 要求安装 DSH 依赖；离线纯源码运行可跳过原生契约。如果 Windows 沙箱拦截测试运行器的子进程管道，用 `node --test --test-isolation=none test/<file>.test.js` 逐文件运行。

原生契约测试使用受控适配器和夹具会话/工具，证明的是运行时集成，不是真实模型准确率、OS 隔离或已认证的 Web/Headless 验收；这些仍在 [ADR-0002 的清单](docs/ADR-0002.md)中。日志分离评估、结果和最终状态，不含原始命令、提示词或密钥；宿主留存由运维管理。
