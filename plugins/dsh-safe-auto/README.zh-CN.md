# 安全自动

<!-- release-state-note -->

[English](README.md)

新增一个「安全自动」权限档位。普通操作照常在工作区沙箱里运行；需要审批的请求交给审核模型判断，通过就只放行这一次，拒绝就把原因告诉智能体。做法参考 Codex 的自动审核（auto-review），始终保持工作区沙箱隔离，而非切换到完全权限。

## 安装

```sh
dsh plugin --profile web add @klarkxy/dsh-safe-auto
```

把 `web` 换成你的 profile 名，安装后重启 profile。

## 使用

在输入框旁的权限菜单中选择「安全自动」。选中后仅对当前会话生效，选回其他档位即关闭。

在「设置 → 会话管理 → 安全自动」中选择审核模型、思考强度和额外的审核要求。模型留空时跟随默认辅助模型；没有设置默认辅助模型时，跟随当前会话模型。默认辅助模型是共享设置：在「设置 → 会话管理」里设置一次，所有跟随它的功能都用同一个模型。设置在别处改动时本页会自动同步。

模型列表读取失败或部分提供商不可用时，可在设置面板点击「重试」。重试会保留审核配置和未保存的草稿。

## 审核历史

在「设置 → 会话管理 → 安全自动 → 审核历史」里查看插件记录下的每一次审核。可以按搜索词、会话、工具、结果、风险和起止时间筛选，再逐页翻看。点开一条记录会看到这次审核的全貌：触发原因、实际送审的参数、送审内容、判定结果、每次尝试的 token 用量，以及放行的调用后来是否实际执行。

可以导出单条记录，或导出符合当前筛选条件的全部记录，格式为 JSON。导出全部时逐页拉取，可随时取消；仅在完整导出成功后写入文件。

历史记录涵盖安装审核历史功能之后的每次审核，持久保存在 Harness profile 中。

### 工具

| 工具 | 作用 |
|---|---|
| `safe_auto_history` | 只读查询当前会话的审核历史：`list` 返回摘要列表，还有后续记录时提供下一页游标；`get` 返回单条完整记录。跨会话历史可在「设置 → 会话管理 → 安全自动」查看。查询历史仅读取本地记录，保持审核模型空闲。 |

## 会审核什么

- `write`、`edit`、`bash`、`pwsh` 申请的沙箱提权。
- 少量危险命令，在沙箱内也会先送审：强制删除（`rm -f`、`Remove-Item -Force`、`del /f`、`rd /s /q`）和打开网址。
- 其他插件或工具在这个会话里发起的审批请求。

读文件、搜索、构建、测试这类常规操作直接运行，无需送审。

## 审核怎么判断

- 审核模型会看到对话记录、当前工作目录、沙箱工作区边界和这次操作的完整参数。只有你发的消息算授权，智能体的说明、工具输出和文件内容都只作参考；早先的审批结论是另一次调用的记录，不构成这次的授权。
- 审核读的是对话当前的样子：你改写过的请求和它产生的那一轮都不再算依据；审核进行期间有新消息到达，这次审核即作废。
- 低风险和中风险的操作放行；高风险只在你明确要求且范围有限时放行；严重风险（例如把密钥发到外部、大范围不可逆删除）一律拒绝。
- 审核超时、返回字段缺失或含未知值、出错或缺少可用模型时，请求按审核失败拒绝，智能体可以重试一次或向你询问。
- 跟随默认辅助模型的审核，每次都会先读取这个共享默认。读不到时按审核失败拒绝，而不是换一个你没选过的模型来审。
- 同一轮对话里连续拒绝 3 次，或最近 50 次里拒绝了 10 次，就暂停自动审批，等你发下一条消息。

## 限制

- **这不是安全边界。** 审核方是语言模型，可能判断错误。请保留原有的沙箱、隔离和备份。
- 被拒绝的操作直接把原因返回给对话中的智能体。想放行时直接在对话里告诉智能体，它重试时审核会看到你的批准。
- 对话记录超长时会截断最早的内容。
- 操作参数以完整内容送审；完整操作超出审核容量时拒绝自动批准。
- 关闭安全自动或修改审核设置，会使尚未完成的审核失效。
- 安全自动仅作用于顶层会话，子代理会话沿用原生审批流程。
- 同一 profile 中请单独使用本插件处理自动审批。
- 历史保存脱敏后的审核依据。已知凭据会尽力遮盖，未知格式的敏感内容仍可能保留；超大或无效的操作会明确标注记录范围。
- 审核结论、观察到的实际审批与工具结果分别记录；未观察到审批或执行结果时会明确标注。本地审核记录作为普通 profile 数据保存。
- 自动批准以审核记录成功落盘为前提。
