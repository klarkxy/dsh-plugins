# Semantic authorization and bounded execution evidence

Status: implemented for `0.2.0-rc.2`; its no-human-fallback decision is superseded by [ADR-0005](ADR-0005.md). Live-model accuracy and installed-profile acceptance remain separate from automated contracts. Sources checked on 2026-10-05.

## Reference and decision

Codex separates the exact proposed action, retained human authorization and untrusted implementation evidence. Its [review policy template](https://github.com/openai/codex/blob/main/codex-rs/prompts/templates/guardian/policy_template.md) judges authorization by material semantics and recognizes necessary implementation steps. Its [prompt builder](https://github.com/openai/codex/blob/main/codex-rs/core/src/guardian/prompt.rs) supplies a compact transcript and the exact request. [Auto-review documentation](https://learn.chatgpt.com/docs/sandboxing/auto-review) describes read-only investigation and distinguishes timeout from an unsafe action.

Adopt those principles inside the existing single-call gate. No new approval service, persistent authority store, general shell interpreter, reviewer tool execution or command whitelist is introduced. Safe Auto retains a stricter floor than Codex's default: at least medium direct authorization, bounded effects, and only low/medium risk qualify for automatic permission.

## Authority

Collect direct-human text in chronological order after excluding child sessions by durable header metadata. Retain earlier authorization across follow-ups and apply later restrictions and revocations. Assistant messages, tool results, plugin feedback and quoted text do not grant permission. Bind the full selected authority to the live execution and recheck it after awaits.

Retain all human text within 12 KiB; do not preserve an old grant by dropping an intervening restriction. Sensitive or nontext messages and overflow mark authority incomplete and prevent review. This intentionally requires a fresh, fully scoped conversation rather than a model-generated summary that could change authority. Only retained session events are available; the plugin cannot recover instructions removed by host compaction.

## Evidence

Use the pinned host filesystem's `resolve`, `contains`, `stat`, `readBytes` and `processPath` APIs. Read package manifests for the effective working directory and workspace root, plus directly referenced local code and file references in relevant package scripts/hooks. The hint scanner only locates evidence; it does not prove shell semantics or authorize execution. Maintained POSIX `shell-quote` and argument-string packages were considered, but they do not supply PowerShell semantics and add a dependency without improving this bounded locator.

Resolve canonical targets inside the canonical workspace root; exclude protected paths before and after resolution. Cap at eight files, 6 KiB per file and 12 KiB overall. Decode strict UTF-8 and withhold other encodings and control-byte content. Screen known secret patterns, including quoted and decoded JSON keys, before sending evidence. This detector is not a guarantee against arbitrary secret encodings. Mark unavailable, excessive and withheld evidence explicitly. Do not recursively inspect imports, dependencies or every workspace package.

Record canonical paths, opaque filesystem versions and SHA-256 content digests, including absent manifests. Re-resolve and reread before returning `allowed-once`; changes invalidate the review. This closes stale-evidence grants during review, not the race between approval and actual execution.

## Failure and feedback

Explicit model denial remains `rejected`; uncertainty, timeout, malformed response, missing reviewer and exhausted budget return native `unavailable`. Neither delegates or grants permission. Only semantic denials increment the denial streak. All attempted model calls keep their reservation; non-denials reset the streak.

The `tools/execute` wrapper adds bounded classification and recovery feedback to failed result content. The real ToolRuntime contract verifies that feedback survives normalization. The `tools/result` event remains a read-only observer. Model rationale is labeled untrusted and never copied to logs; secret-bearing rationale is withheld.

DSH 0.1.7-rc.2 approval and user-question services both dispatch arbitrary composed waterfall answerers. Neither proves human provenance. A direct human fallback therefore remains unsupported; uncertainty is not delegated through either chain. No fake human channel is added.

The default combined prompt/input budget increases from 8 KiB to 32 KiB. Existing explicit profile limits remain valid. Reviewer route, effort, single-call execution identity, cancellation, lifetime, native `never`, settings revocation and protected-file controls remain enforced.
