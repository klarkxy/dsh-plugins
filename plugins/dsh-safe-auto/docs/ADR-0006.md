# Static shell proof: read-only fast path and AST-level hard rules

Status: implemented in the unpublished `0.2.0-rc.3` work, following explicit user approval on 2026-10-06. Complements ADR-0001 (0.1.x preflight removal) and ADR-0002 (execution-bound review).

## Context

0.1.x carried a static layer (ordinary-command review, workspace/shell candidates, `shadow`/`smart`/`unattended` modes). ADR-0001 removed it because it was a fuzzy candidate-rule system: enrolled strings pretended to be policy, and three modes made the effective boundary unreadable. Two real problems remained after the removal, however:

- The hard-rule layer recognized dangerous programs only as the first word of a bare, whitespace-clean command. `ls | rm x`, `sudo rm x` or `time rm x` in a compound command bypassed the deterministic layer entirely and leaned on the model to notice.
- Every escalation, including a provably read-only `git status`, paid one reviewer call of latency and budget.

Two sibling harnesses informed the redesign. ZCode's build/edit modes downgrade provably read-only Bash invocations through a strict AST walk plus per-command policies, and its reserved `auto` mode (never implemented, fail-closed `mode.auto.unimplemented`) shows the intended shape of "low risk goes automatic." Codex's execpolicy separates a strict fully-literal parse (allowed to prove safety) from lossy heuristics (allowed only to flag danger), aggregates compound commands with every-semantics, and fails closed when parsing cannot explain the whole command.

## Decision

Parse shell commands with `unbash` (Apache-2.0, zero-dependency bash parser, runtime dependency) in a new `src/shell-command.js`. The analysis accepts only a fully literal command: Statement/AndOr/Pipeline/Command/Time nodes, no backgrounding, no heredoc bodies, and every word, assignment value and redirect target free of expansions, globs and tilde prefixes. Anything else returns `ok: false` and changes nothing about the existing pipeline.

**Read-only fast path.** When the structural assessment reaches `review`, a fully literal bash escalation is granted `allowed-once` with `STATIC_READONLY` only if every invocation satisfies its complete positive grammar. Exact case-sensitive POSIX executable names select policies. `rootName` normalization (paths, case and Windows suffixes) is only for danger detection. There are no arbitrary-argument policies, unknown option abbreviations, general short-option clusters or deny-list proofs. Registered options have exact arity and value validators; each operation checks input/output operand counts and incompatible modes. `--` makes later flag-shaped tokens filenames. Unsupported syntax falls back to the existing reviewer/manual channel, not a hard denial.

Ordinary `ls -la`, `cat input | jq .name`, `grep -rn pattern src`, `find . -name "*.md"` and `ps aux` remain fast reads. `rg --pre`, archive/helper modes in `file`, reverse/output forms of `xxd`, a second output operand in `uniq`, executable pagers and mixed Git read/write operations do not qualify. `date --debug` and `--resolution` take no values, so they cannot consume a following set option. Only streaming `sort --check` qualifies: ordinary sorting can spill to temporary files. Bash `printf -v` and `%n` do not qualify because they assign shell variables.

Environment prefixes are checked before handling empty argv. Only explicit bounded values for CI, locale, color, terminal dimensions and UTC/GMT timezone settings are allowed, without duplicate names. Assignment-only statements do not qualify, including safe-looking assignments, because they persist into later compound invocations. Thus `PATH=.; ls` and `PAGER=node; git log` cannot alter subsequent resolution inside a supposedly read-only compound. PAGER, GIT_PAGER, Git configuration/transport and dynamic-loader environment prefixes are excluded.

**Git proof scope.** A read-like subcommand is insufficient. Worktree status/diff can invoke configured clean/process filters during index refresh or conversion; no generic argv-only switch disables every named filter, so these operations always fall back. Supported object/index reads require the original global `--no-pager --no-optional-locks --no-lazy-fetch -c core.fsmonitor=false`. Diff proof is limited to `--cached`/`--staged` with at most one operand (also excluding implicit two-path no-index mode) and requires `--no-ext-diff --no-textconv --ignore-submodules=all`. History reads require the same diff controls, `--no-show-signature`, and a supported fixed format (`--oneline` or a bounded non-signature format), excluding `%G*` verification placeholders. Exact version calls and `git --no-pager config` with one getter/list operation and correct arity are independently narrow reads. Editors, reflog mutations, transport commands, external diff/textconv/filter modes, unknown options and mixed config mutations never qualify. Controls are recognized in the unchanged original argv; nothing is prepended or rewritten.

`pwsh` always uses review because its grammar differs. The static grant keeps the complete execution binding, one claim, cancellation, control epoch, audit and recheck-before-grant machinery. It consumes no model review budget and touches no denial streak. Profile key `staticReadonly` (default `true`, operator-owned, not UI-editable) disables the fast path.

**Native approval ownership.** In pinned DSH 0.2.0-rc.2, ApprovalService applies native policy and cancellation, then dispatches `approval/request` through a waterfall. A genuine foreign request (Blueprint order or Classmates model approval) without a Safe Auto execution store calls `next()`. Any existing owned store stays fail-closed on mismatch, inactivity, staleness or a prior claim, and absent-store requests impersonating owned bash/pwsh/write/edit tools reject. Owned human takeover continues only through the authenticated plugin queue, never a downstream automatic answerer.

**AST-level hard rules.** A refusal-only AST walk checks literal program roots (basename, Windows extensions stripped, `command`/`builtin`/`nohup`/`time` wrappers unwrapped over the known prefix, depth-capped) against the dangerous-root table and denies `DANGEROUS_PROGRAM`. Unknown later arguments do not soften a known dangerous root. Unparseable commands keep the legacy bare-command check. Unexplained expansions still require review; partial decoding never grants permission. Hard refusals stay unsoftenable by model or human.

Hard protected-path/secret checks consume decoded literal argv, assignment and redirect values, including quote concatenation and option/object-path values. A refusal-only AST walk retains known literals even when a different dynamic fragment or control-flow node prevents a whole-command proof. Its 32768-character parse bound covers the maximum 32768-byte reviewable argument budget; static proof retains its stricter 10000-character bound. These hard refusals apply to every approval route and cannot publish a reviewer/manual override. Quote context is preserved in proof: unquoted glob/brace fragments invalidate it, while fully quoted filename patterns remain literal. File-opening `/dev/tcp` or `/dev/udp` redirections cannot prove read-only because Bash implements them as sockets, including quoted and numbered-fd input redirects. They fall back to review; ordinary file input, fd merges and `/dev/null` output keep their rules.

`git ls-files -m`/`--modified` is also excluded: Git's `show_files` calls `ie_modified` and content conversion for that mode. The admitted cached/stage listing does not inspect worktree content; deleted/other listings only stat or enumerate with the same fixed controls. EOL, custom-format and submodule-recursion modes remain unsupported.

## Relationship to ADR-0001

This is not the return of candidate rules. Nothing is enrolled, persisted, prefixed or remembered: every call is re-proven from its exact bound arguments, and the safety proof requires a fully literal command. Refusal-only partial decoding may recognize a known hazard, never establish safety. Unprovable commands flow into the unchanged reviewer path with the same budgets, and the human confirmation channel of ADR-0005 is untouched. The 0.1.x modes and profile keys remain retired and still fail validation.

## Trust and limitations

The accepted trust boundary remains operator-trusted PATH resolution and installed runtimes. This is a proof over the unchanged command text, not binary identity, shell-function integrity or runtime attestation. Within that boundary the supported grammar excludes known filesystem writes, network/helper execution and persistent environment changes; it is intentionally incomplete. Output can still expose workspace contents to the model context, which is already trusted with them. Unsupported commands cost review, never a new denial. Parser or grammar defects may produce incorrect proofs; strict parsing and positive rules reduce that risk but do not establish an absolute guarantee.

The fast path skips execution evidence collection and the model assessment row. Its approval audit row carries `STATIC_READONLY` with `static` as the source. Local `staticReadonly: false`, disable or unload remains the rollback. Tests challenge helper/value/cluster alternatives, output operands, persistent assignments, executable identity and Git configuration effects, then exercise the actual adapter fallback and pinned Cordis/ToolRuntime/ApprovalService waterfall. These are source and fixture-runtime checks, not live OS confinement or real-user acceptance.
