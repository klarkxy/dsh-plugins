# Timed human confirmation

Status: implemented in the unpublished `0.2.0-rc.2` work, following explicit user approval on 2026-10-05. Supersedes ADR-0004's no-human-fallback limitation.

## Behavior

Keep automatic model passes. For a structurally eligible call, a model refusal, uncertainty, timeout, unavailable reviewer or exhausted model budget offers a manual confirmation. Model risk classification remains an opinion; the user can explicitly approve that exact action. Native `never`, deterministic hard refusals, unsupported/unbound execution, changed evidence, audit failure and cancellation remain terminal.

`AUTHORITY_CONTEXT_INCOMPLETE` blocks automatic review but may receive fresh one-call UI authorization. Rerun every action/host/schema/secret check with only that historical-input flag waived; keep the original live binding. Incomplete private history is never sent to the reviewer or dialog. No other structural refusal is waived.

Default `humanApprovalTimeoutMs` is 60000, operator-owned and separate from the model deadline; zero disables takeover. Publish the exact action, permission change and bounded reviewer opinion to a runtime-local queue. Start the server-monotonic deadline when publishing. Only the first session-bound answer consumes the unpredictable request ID. No answer before expiry means rejection; late/duplicate answers never grant.

The existing authenticated `/dsh-safe-auto` browser route owns `approval.list` and `approval.answer`. It bypasses the settings serializer so waiting never blocks approval or revocation. Direct browser JSON requests require fetch mode (`cors` or `same-origin`), destination (`empty`) and same-origin/same-site metadata. The DSH 0.2.0-rc.2 desktop carrier checks the application origin itself, removes Origin and Sec-Fetch-Site, and forwards with its Host-issued cookie. Installed Electron 44 protocol requests omit Fetch Metadata; the carrier's Node fetch adds `mode=cors` but no destination. Missing destination is admitted only with that mode and both Origin and site absent, after Host authentication and source checks. Explicitly invalid metadata remains rejected. No automatic waterfall answerer is consulted and no model tool is registered for answering.

## Lifetime and integrity

Existing execution identity, complete arguments, human-context and control revision bindings remain live throughout the wait. Cancellation, settings changes, permission changes, session replacement, detach and runtime disposal invalidate requests. The queue has a fixed 32-request cap, is not persisted, and clears timers/listeners when each request settles.

Approval claims the queue entry synchronously before file checks. Reverify original captured evidence using a fresh bounded signal combined with execution/runtime cancellation. Never recollect and silently replace old evidence. Check deadline and live binding immediately before the grant. The 30-second model lease applies only to model passes; it does not expire an otherwise valid 60-second human window. A successful manual grant resets the semantic denial streak but does not refill model-call budgets.

## UI

The composer permission component polls serially while Safe Auto is enabled, including before a request exists. An official body-portaled Modal shows exact plain-text shell commands or complete write/edit effects, cwd, permission change, model opinion and countdown. It remains usable while the agent locks the composer. Reject receives initial focus; closing via Escape, mask or close button rejects. Approve says “only this call.” Writes are never retried automatically; uncertain transport results trigger a fresh read. Session changes/unmount discard stale responses.

The browser countdown derives from server `remainingMs` and a local monotonic clock, with network time subtracted. It cannot extend the server deadline.

## Trust and limitations

Authentication, origin checks, Fetch Metadata and request IDs protect the browser channel against accidental and cross-site answers. They do not prove physical human action. Authenticated clients/carriers and same-process plugins remain trusted; an actor able to steal client authentication or forge a trusted client can forge an answer. The plugin does not claim confinement against that actor. Transports missing fetch mode cannot use manual confirmation; pending requests then expire. Missing site metadata is accepted only when Origin is also absent; missing destination additionally requires `mode=cors`, matching the authenticated desktop carrier. Headless execution with no UI controls retains the non-grant path.

Evidence remains partial and review-to-execution file races remain possible. No new persistent storage, credential access, service, framework or dependency is introduced. Local disable/unload remains the rollback.
