# 副驾协作

给当前助手配一个常驻的原生搭档：主助手分派一个有边界的任务，读回确切结果，再决定采纳还是要求修改。会话、工具、权限、模型与执行记录仍然由 DeepSeek Harness 负责。

[English](../README.md)

插件默认关闭。在宿主的插件设置中启用「副驾协作」即可，不需要为每段对话再开一次开关；启用后已有的写作类对话同样会参与，子会话不会变成新的主助手。

## 安装

需要 Node.js ≥22 与兼容的 DSH `0.1.7-rc.2+` 宿主（peerDependencies 使用 `>=0.1.7-alpha.1` 这类开放下界）。若所用 DSH 发行版未内置本插件，可先安装，再通过宿主插件配置启用 `fusion` 入口：

```sh
npm install @klarkxy/dsh-fusion
```

## 工作方式

主助手负责讨论、规划、维护与审阅，执笔搭档负责生成精确候选。每次修订及后续任务沿用同一个搭档会话。

通过主助手审阅的文本仍然是候选，不会自动改动你的正文：在任务卡片上点击「预览采用」打开候选预览，再在预览中点击「确认采用」才会写入。写入前，宿主会重新校验来源版本和未保存草稿。原文已经变化时，候选会保留，但不能覆盖新的正文：请保存需要保留的草稿，并让助手基于当前内容重新修订。

正文与大纲的文本提案都走执笔搭档，因为普通文件夹项目模型无法可靠判断文件内容类型。结构性操作与受支持的维护工具仍由主助手完成。候选文本不会流式写入正文。

在原生 Web 中，执笔搭档沿用既有的原生工具与权限系统，协作卡片会链接到对应的原生执行记录。通用任务在执行过程中可能已经改动了文件，因此「审查通过」只是审查状态，并不表示还有一份待采用的正文改动。

## 模型与生命周期

搭档是一个原生子会话：路由在配对创建时固定，之后每次请求都会复核。新建配对依次按插件页选择、当前会话模型、宿主默认对话模型解析路由；都解析不到时不配置任何模型。已有搭档保持创建时选定的路线，修改设置不会改动正在使用的配对。

## 任务生命周期

每个配对同时只运行一个任务，修订与后续任务复用同一个原生子会话。「停止协作任务」会取消正在进行的工作，关闭卡片只关闭视图。停用插件会停止它自己持有的工作，并保留记录与候选。

进程重启不会重放状态不明的信息或文件写入。请先核对任务卡片与原生执行记录，再明确恢复或重新通知主助手。若写入被中断，Fusion 会把已持久化的写入意图与当前文件比对，既不会自动重试状态不明的写入，也不会覆盖作者之后的新修改。

任务卡片给出当前状态、候选预览、「停止协作任务」和恢复入口。报告已保存但通知未确认时，可以重新通知主助手继续审阅，无需重新启动执笔。

## 插件页设置

「设置 → 插件 → 副驾协作」下有**副驾模型**菜单，可留空，只在新建配对时生效：保存某个路由后，新建搭档会把它作为固定模型；留空则使用当前会话模型，再回落到宿主默认对话模型。已有搭档保持创建时选定的路线，修改这一行不会改动正在使用的配对；解析不到任何模型时会明确报错。保存路由只表示选定模型，不代表已连通。

## Agent 工具

主助手持有五个工具，执笔搭档持有一个汇报工具。工具身份在注册时绑定，每次调用都会再次校验，其他 Agent 无法借用。

主助手（Lead）：

- `fusion_delegate`：把一个有边界的任务委派给同一个持久搭档。写作任务中，执笔基于主助手提供的带版本原始目标撰写精确文本；通用任务保留普通执行工具，接管前需显式取消。
- `fusion_read`：读取已保存的精确候选及其哈希；审阅这份内容而不改写。
- `fusion_review`：按候选 id 与哈希审查。accept 仅是模型审查——是否采用仍由作者决定；revise 必须给出具体反馈；reject 结束任务。
- `fusion_decide`：答复搭档的决定请求，或带反馈显式恢复被中断的任务，复用其持久会话。
- `fusion_cancel`：在显式接管前取消本方搭档任务；不影响无关子会话，也不撤销已经写入的文件。

搭档（Sidekick）：

- `fusion_report`：以唯一 reportId 汇报当前任务的精确候选或决定请求；绝不直接写稿，确认后不会重新生成或重复发送。

## 包入口

本包不依赖任何应用私有包。原生 Web 适配器复用既有的对话与子会话导航。

默认导出注册插件；`./contracts` 导出浏览器安全的公开记录（RPC 通道、工具名、任务与候选类型）；`./host-contracts` 定义宿主侧 `fusionWriting` 端口；`./client` 是浏览器端界面包。

宿主提供一个窄接口 `fusionWriting`，只有宿主代码能拿到这个应用端口。浏览器命令只携带已保存的候选标识与作者操作，不会携带替换用的候选内容，也不会指定新的写入目标。

## 开发检查

- `pnpm --filter @klarkxy/dsh-fusion typecheck`：类型检查。
- `pnpm --filter @klarkxy/dsh-fusion test`：确定性的服务与原生边界测试。
- `pnpm --filter @klarkxy/dsh-fusion build`：生成生产环境界面包。

这些确定性集成测试用于确认接线与生命周期行为，不衡量线上模型的写作质量，也不衡量 provider 的缓存节省。
