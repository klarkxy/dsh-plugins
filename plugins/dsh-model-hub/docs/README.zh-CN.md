DeepSeek Harness 跨插件模型设置枢纽——**开发预览**。打开「插件 → 模型枢纽」，
按插件、用途或当前模型搜索，在紧凑列表中直接选择模型，改动立即由所属插件保存。
已经打开的插件页会自动刷新已保存的模型设置。有未保存草稿时保留草稿并提示冲突，
显式重新加载才丢弃草稿。断线重连后重读最新设置；订阅不可用时保留手动刷新入口。

对应更新后的插件加载时，枢纽覆盖会话标题、Git 提交、安全审核以及 ChatGPT。
ChatGPT 使用独立的 Codex 模型目录和默认模型。

「子代理阵容」页签管理宿主的子代理模型白名单：启用开关、添加、替换或移除模型
都直接写入原生 `subagent-model-selection-settings` 设置（带版本冲突保护），
宿主约束照常生效。每个模型还可以标注一句「任务倾向」，倾向保存在
`<profile>/data/model-hub/cast.json`，并作为只读提示注入系统提示——主智能体
委派子代理时参考这些倾向自行选模型，倾向不做硬约束。该页签接管后，字段总览
不再重复显示这组原生设置。

先添加模型才能启用阵容，移除最后一个模型时会同时关闭开关。白名单约束显式选择的
子代理模型；不指定模型时仍继承父会话。任务倾向有独立的持久修订号，多个页面同时
修改时检查冲突。旧 v1 文件在首次成功保存时迁移；损坏或不可读时保留原文件并显示
恢复提示，原生阵容控制仍可使用。

第三方插件的 volatile 模型字段仍通过原生 `settings.describe()` 发现，支持深层
schema、数组、字典和组合字段。使用其他存储方式的插件可以通过
`@klarkxy/dsh-plugin-kit/model-settings` 提供模型字段；枢纽不读取其私有存储。

刷新会同时更新设置和模型列表。读取失败的来源保留错误说明；保存发生冲突后，
刷新并重新选择。设置版本和插件实例标识防止旧页面覆盖新设置；提示词、回退开关
等其他字段保持原值，包括原生模型对象内部的附加字段。
保存确认与页面刷新分别处理；写入成功而刷新失败时，页面明确提示已保存，可单独
刷新，不会自动重复写入。

诊断报告另行记录：

1. 已安装插件的 `settings.describe()` 投影里有哪些模型路由字段
   （通过 `@klarkxy/dsh-model-route` 检测，标记或裸形状均可）？
2. 自定义 schema 标记能否穿过宿主投影？本插件自己的 Config 带两个自检字段：
   一个用自定义 `x-model-route` 键标记，一个用 schemastery 渲染器 role 通道。

报告会写日志，并落盘到 `<profile>/data/model-hub/probe-report.json`，
每次 `settings/document-updated` 事件后刷新。

实际原生数组元素显示为独立行。空集合显示提示行，需要先在所属插件中添加元素。
恢复原生字段时使用所属插件的继承值或默认值；清除直接数组路由时保留该元素。
各插件提供的模型字段会说明各自的默认模式。

两个自检字段保留在诊断报告中，不出现在模型选择页。此预览尚不包含按天用量统计。

## 安装

需要 DSH 0.2.0-rc.2 或更高版本。安装预发布通道，重启 profile 后打开「插件 → 模型枢纽」：

```sh
dsh plugin --profile web add @klarkxy/dsh-model-hub@next
```
