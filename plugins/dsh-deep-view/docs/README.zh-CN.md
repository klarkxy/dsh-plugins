# Deep View 智能界面

<!-- release-state-note -->

Deep View 在助手回复中组合智能界面。普通 Markdown 可以自然衔接原生图表、对比、流程步骤、指标、可调估算和回答控件，然后继续正文。有些界面可以直接探索：可拖动的数学坐标系、节点图、联动数据探索和地图。卡片内的操作会立即更新同卡片的公式与其他组件，无需再次请求模型。

## 安装

通过 DSH 插件管理器安装 `@klarkxy/dsh-deep-view` bundle，然后启用 **Deep View 智能界面**。包内同时包含 Host 与 Web Client，无需账号或 API 密钥。

## 用法

直接提出方案对比、趋势、流程、可调预算、互动数学图、节点示意图、地图或其他适合可视化表达的需求，也可以明确点名 Deep View。模型会先判断普通文字是否足够，只在界面确有帮助时加载按需提供的 `deep-view` skill。

有两种互补的界面入口：

- **正文界面。** 模型在段落之间放置 `deepui` 声明，Deep View 将其替换为当前位置的原生界面；流式生成时，JSON 完整后即可显示。图表、表格、指标和交互估算留在阅读顺序中，不再统一搬到回合末尾。
- **任务界面。** 需要在回复出现前展示进度，或需要 Host 校验并直接提交回答时，模型调用 `show_view`。当前进度使用一个可替换的活动视图。待答界面生成期间可以位于输入框上方，回复后留在正文中，同一时间只有一个可编辑实例。

两种入口使用同一套组件。布局组件为 `stack`、`row`。展示组件为 `text`、`metric`、`table`、`chart`（`bar`、`hbar`、`line`、`area`、`donut`）、`progress`、`callout`、`sources`、`steps`。`slider`、`number`、`choice`、`toggle` 是本地输入。公式写作 `{ "=": "price * count" }`，支持算术、比较、条件表达式和固定函数集，不执行 JavaScript。

另外四类组件既能展示也能交互：

- `math`（Mafs）绘制坐标系，支持一到四个可拖动坐标点，并按声明的 domain、range 画出最多四条 `f(x)` 曲线。视图固定在该声明范围内，不平移、不缩放；公式和其他组件可以读取每个点的实时坐标。
- `flow`（React Flow）绘制声明好的节点图。可以平移、缩放、拖动节点排布，并选中一个节点；同卡片可以读取该选择。
- `explore`（Vega-Lite）将声明的内联行数据画成散点图，并把一次选择联动回卡片：点击数据点选择分类，或拖拽选择 `x`/`y` 区间；可折叠表格列出同一批数据。
- `map`（MapLibre）在地图上显示声明的地点与路线，并始终在地图旁渲染地点列表；同卡片可以读取选中的地点。

同一张卡片里的状态是共享的：输入、数学点坐标，以及节点、地点或散点的选择，都会参与该卡片的公式、指标和表格，并写入可读回答。

`options`、`confirm`、`form`、`submit` 用于回答。`show_view` 的回答在提交前由 Host 按卡片声明的控件和当前 revision 校验。正文界面使用 **填入输入框**，由你检查并亲自发送；不会静默发送，也不会未经确认替换已有草稿。选择、填写结果、可调输入和界面选择会包含在可读回答中。

`show_view` 也可以更新已有卡片而不是新增一张：模型带上卡片的 `view_id` 和它上次看到的 revision，卡片在同一位置被下一版替换。过期的 revision，以及针对已被替换或已关闭卡片的回答，会被拒绝，而不会覆盖新状态。

直接提交的回答，以及能够明确对应的输入框回答，会在刷新或重新打开会话后随界面恢复。图表支持键盘查看、表格切换和复制 CSV；已回答过的卡片变为只读。

## 限制

- 界面由模型按需选择；不会强制所有回复采用可视化布局，也不改变其余助手 Markdown 的行为。
- `deepui` 围栏在完整 JSON 就绪后渲染，不是任意节点级 UI patch。格式错误的声明仍可作为普通代码查看。模型是否主动生成界面取决于所选模型和提示。
- 这些组件是封闭的原生控件，不是图表、图结构或地图描述语言：不执行任意 JavaScript 或 HTML，也不提供 `html` 组件；`explore` 只接受内联标量行数据，不接受 Vega-Lite spec 或远程数据源；`map` 只接受坐标，不接受样式 URL、瓦片服务或密钥；`flow` 只接受声明的节点和连线，不接受自定义节点组件。不包含 PNG 导出。
- `show_view` 的活动更新以工具调用为边界；不会从其他长时间运行的工具内部连续推送进度，也不会改写历史工具结果。
- 只有真人顶层会话或普通会话分叉中当前有效的 `show_view` 界面能通过 Host 提交；委派子代理不能收集直接回答。插件重启后待回答记录会丢失，但保存的内容仍可在会话中查看；正文围栏交互使用填入输入框。
- 卡片只在仍有效时可交互：待回答界面在回答后或收到另一条普通用户消息后关闭，已回答卡片显示为只读，尚未提交的本地修改不会自动持久化。不要用界面收集密码、密钥或 token。
- 地图加载固定的远程示例底图，不接受其他样式源。没有网络、没有 WebGL 或底图加载失败时，卡片会给出提示，地点列表仍可用于选择地点。
- 每张卡片有大小上限：组件、曲线、图节点、数据行或地点过多时会被拒绝，而不是静默截断。
- 主题与实际渲染取决于安装的 DSH Web Client；源码构建成功不等于已完成运行时或视觉兼容验收。
