# @klarkxy/dsh-git-commit

在对话里直接把工作区修改提交到 git。每个对话线程的右上角有一个 **提交** 按钮：
点一下打开弹层，确认分支、文件数量和将使用的模型，再点一下即可把会话工作目录
所在仓库的全部未提交改动分次提交。

模型会把改动整理成若干个内聚的提交并生成提交信息，然后按顺序逐组创建限定路径的提交。模型路由由
[@klarkxy/dsh-ai-services](https://klarkxy.github.io/dsh-plugins/plugins/ai-services/)
提供：在「AI 服务」设置里提前给 **Git 提交**（`git-commit.plan`）用途配置专用模型；
没有配置时依次回退到 normal 角色和默认对话模型。模型调用失败或返回非法分组时，
改动会合并为一个兜底提交。

## 使用

1. 打开一个工作目录位于 git 仓库内的对话。
2. 点击线程右上角的 **提交** 按钮。
3. 在弹层里确认并等待执行完成。
4. 面板会列出创建的每个提交（哈希 + 信息）。

会话运行期间按钮不可用。宿主在提交前还会再次检查，规划期间工作区变化时会中止。

## 说明

- 每个选中文件按当前工作区内容提交。其他分组的已暂存修改会保留到对应分组提交。
- 未跟踪文件也会提交；较小的文本文件会把内容预览发给模型，二进制文件只列路径。
- 插件只做 commit，不会 push。
