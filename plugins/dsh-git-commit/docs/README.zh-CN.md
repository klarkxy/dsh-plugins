# @klarkxy/dsh-git-commit

在对话里直接把工作区修改提交到 git。每个对话线程的右上角都有一个 **提交** 按钮：
点一下打开弹层，确认分支、文件数量和将使用的模型，再点一下即可把会话工作目录
所在仓库的全部未提交改动分次提交。

[English](../README.md)

## 安装

需要 Node.js ≥22。若所用 DSH 发行版未内置本插件，可先安装，再通过宿主插件配置启用
`git-commit` 入口：

```sh
npm install @klarkxy/dsh-git-commit
```

## 工作方式

模型会把改动整理成若干个内聚的提交并生成提交信息，然后按顺序逐组创建限定路径的提交。模型路由由本插件自己的设置行提供：在「设置 → 插件 → Git 提交」提前配置**提交规划模型**即可固定专用模型；没有配置时依次使用当前会话模型和宿主默认对话模型。模型调用失败或返回非法分组时，本次提交会被**拒绝**，不会暂存也不会提交任何内容——模型没有规划过的提交不是你要求的提交。想要回到旧行为，可以在插件页打开**模型不可用时仍然提交**，此时全部改动会合并成一个提交，由插件代写提交信息。

## 插件页设置

「设置 → 插件 → Git 提交」下是本插件需要的设置项。**提交规划模型**用于提交规划调用，
可留空：保存某个路由后，对应该调用会使用这个显式模型；留空则使用当前会话模型，
再回落到宿主默认对话模型。对话头部面板会显示实际生效的是哪一种。只有这个调用受影响；
保存路由只表示选定模型，不代表已连通。**模型不可用时仍然提交**默认关闭，只在
规划完全没有产出时改变行为。

## 使用

1. 打开一个工作目录位于 git 仓库内的对话。
2. 点击线程右上角的 **提交** 按钮。
3. 在弹层里确认，然后等待执行完成。
4. 面板会列出创建的每个提交（哈希 + 信息）。

会话运行期间按钮不可用。宿主在提交前还会再检查一次，规划期间工作区发生变化时会中止本次提交。

## 说明

- 每个选中文件按当前工作区内容提交。属于其他分组的已暂存修改会保留到对应分组提交。
- 未跟踪文件也会提交：较小的文本文件会把内容预览发给模型，二进制文件只列路径。
- 插件只做 commit，不会 push；push 仍由你手动决定。
