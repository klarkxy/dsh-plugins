# 会话管理本地候选版本

本目录保留宿主补丁、插件安装包、验收记录和独立审查结果。它实现跨工作目录的会话查找与分页读取、复制线程 ID、同一会话内的安全重试与编辑重发，以及带独立工作目录的自由聊天、分叉和真实删除。

## 使用现有验收构建

在仓库根目录运行：

```powershell
node host-patches/thread-management/start-local.mjs --check
node host-patches/thread-management/start-local.mjs
```

启动器检查补丁涉及的源码哈希、冻结的完整编译产物和官方客户端构建记录，再启动候选 Web 宿主。它按补丁哈希使用仓库 `.scratch/thread-management/local-home-<哈希前缀>` 下的独立配置、会话与工作目录，保留早期候选目录。模型需要在这个独立应用中配置；验收使用假模型，未测试真实提供方的持续运行。现有桌面应用没有安装、重启或覆盖。

`plugins/dsh-session-manager` 以 `0.1.0-rc.1` 进入 npm `next` 预发布通道；本目录保留已验收的 `.tgz` 和其精确校验值。基础宿主可用跨目录查找、分页读取和复制线程 ID；自由聊天和原会话重发依赖本补丁增加的宿主能力，只在宿主声明能力后显示。不要把插件单独安装成功当作全部能力已启用。

## 从补丁重建

`manifest.json` 记录上游地址、精确基线、补丁哈希、每个最终源码文件哈希、编译产物哈希、官方客户端记录和插件包校验值。请选择新的空目录，不在现有应用或参考镜像中执行：

```powershell
git clone https://github.com/deepseek-ai/deepseek-harness.git <新的宿主目录>
git -C <新的宿主目录> checkout 639ed015397290b3745d163aafe02ffee4aa3f84
git -C <新的宿主目录> apply --check <本目录的绝对路径>/host.patch
git -C <新的宿主目录> apply <本目录的绝对路径>/host.patch
```

在新宿主目录使用 Node 24+ 及 pnpm 11.7.0：

```powershell
pnpm install --frozen-lockfile
pnpm run build:official
```

`acceptance-tests/` 和 `review-tests/` 保留无凭据的验收夹具。分别复制到新宿主的 `.acceptance/` 和 `.review/integrated_host_review/`，以维持夹具的相对引用。真实页面验收还需要将插件安装包解包到 `.acceptance/runtime-plugin/`，仅去掉 `package/` 第一层，不安装开发依赖。从新宿主目录执行 `node .acceptance/prepare-runtime-plugin.mjs <安装包绝对路径>`。已存在的验收包须先保留，该脚本不会覆盖它。

编译产物随平台和工具链变化；新目录重建后需重新运行相应验收，并生成新的构建校验记录，不能沿用此候选的编译哈希。`build-identity.mjs` 只输出记录，不会自行认可新的构建。

## 数据与回退

新宿主会写 V5 会话格式。V4 读取器拒绝 V5 日志；回退时保留新日志及生命周期记录，不把旧应用指向这份独立数据。删除仅作用于用户选择的会话及已证明归属的资源。没有有效所有权证明的自由目录会拒绝清理并保留会话日志。SQLite 搜索索引可重建。

早期一个测试夹具漏设隔离目录，旧校验函数可能尝试创建真实 DSH 目录下的空 `free-workspaces` 父目录。未读取真实会话或凭据；夹具已隔离，校验函数现为只读。该真实目录的先前归属无法确认，已保留。其余验收均使用隔离目录。

源码与测试的许可见 `UPSTREAM-LICENSE`。详细结果见 `acceptance.json` 和 `independent-review.md`。

本轮修复了无分支重试意图在恢复时覆盖更晚输入的风险。恢复会重新核对切点、输入、静默状态以及常驻和冷子线程的副作用；过期意图保留记录，明确拒绝旧请求，同时允许普通新输入和分叉。真实持久化或所有权读取错误仍向上传递，不会被当作过期拒绝吞掉。
