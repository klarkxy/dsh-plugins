Compaction, subagents, jobs, and catalogs

中文：压缩、子代理和后台任务都是「定义 / 提供者 / 消费者」三条缝。换实现时挂新的 provider，不要复制服务。字段的完整列表在生成的 config catalog，不在这篇索引里。

Indexed against dsh-v0.1.7-rc.2 (477b4f420553e8a52c2fbccc464d7561b239c443).

What it is

Several seams follow the same shape as tools and skills: a Service Definition other plugins inject, one or more providers, and a consumer that faces the model. This page records the registration names. It is not a second config catalog.

Contract

Compaction

@deepseek-ai/dsh-compaction performs no condensation by itself. Mount @deepseek-ai/dsh-compaction-basic to register ctx.compaction, and @deepseek-ai/dsh-command-compact for /compact. A custom backend implements compactIfNeeded (automatic pressure or context-overflow), compactNow (one explicit reduction), and compactRegion (a caller-selected range). Measurement is ctx.tokenMeter, not a field on the compaction service. Bracket events run from compaction/start through compaction/end. The family README also lists ctx.toolResultPruner for tool-result pruning.

Subagents

ctx.subagents.registerProvider(provider) registers one backend. provider.name is unique in the layer (spawn, fork, acp, and the other shipped names). The in-process package @deepseek-ai/dsh-subagent-spawn-in-process defaults providerName to spawn. The model-facing row points at that name:

- name: '@deepseek-ai/dsh-subagent'
- name: '@deepseek-ai/dsh-subagent-spawn-in-process'
- name: '@deepseek-ai/dsh-tool-subagent'
  config:
    provider: spawn
    toolName: subagent

The subsystem page states the split explicitly: Service Definition is dsh-subagent (ctx.subagents), providers are sibling packages, and consumers such as dsh-tool-subagent face the model.

Jobs

@deepseek-ai/dsh-jobs defines ctx.jobs: ids, ownership, lifecycle, and completion listeners. @deepseek-ai/dsh-jobs-local runs jobs in-process. Tool authors start work with ctx.jobs.start({ kind, label, owner, run }) as described in the tool cookbook. See Tools.

Catalogs

docs/config-catalog.md is generated by scripts/gen-config-catalog.ts and checked by pnpm run verify-config-catalog. It lists every config: block, with inject, refs, and source. Do not edit it by hand. docs/tool-catalog.md lists model-facing tools. Subsystem pages hold the generated Cordis API (ctx.* methods). When this index and the catalog disagree about a field, the catalog at the pinned commit wins.

docs/cookbook/extension-cookbook.md is the recipe index for cross-cutting plugins, including permission-gate listeners.

How a plugin author uses it

  • Replace condensation by shipping a backend for ctx.compaction. Do not summarize history by deleting session events.
  • Add a child-agent runtime with ctx.subagents.registerProvider, then point a tool row at provider.name.
  • Publish background work through ctx.jobs so cancellation and the job_* tools stay consistent.
  • Look up a config key in docs/config-catalog.md at this commit before adding it to a patch. A key absent from that package's entry is not a loader field.
